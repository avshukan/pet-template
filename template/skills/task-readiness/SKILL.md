# Task readiness

Read the repository's agent instructions, the task and applicable process and
decision documentation. Inspect relevant existing behavior and checks. Use local
work-record conventions if present; do not require a backlog or an application
stack, and do not describe planned behavior as already delivered.

Assess the goal, scope boundaries, testable acceptance criteria, dependencies,
risks and verification approach in proportion to the task. Distinguish observed
facts, proposals, accepted owner decisions and open questions. Reference the
evidence behind material conclusions.

Separate routine implementation choices within agreed scope from material
product, architecture or process decisions requiring owner approval. Reuse
existing authorization; do not reopen settled decisions without new evidence.
For unresolved decisions, give concise options, trade-offs and a recommendation.
For blockers, identify the missing prerequisite and what would resolve it.

Report whether the task appears ready for implementation, needs decisions or
clarification, or has a known blocker. Include a bounded scope and credible
verification plan, or name the gaps preventing them. When the repository
specifies verification commands, list the exact relevant commands in the plan.
Do not invent commands or claim checks were run when they were only proposed.
This is a recommendation, not owner acceptance or permission to implement or
merge. Use existing record formats and states only when documented and
authorized; otherwise report in the conversation. Do not create new workflow
machinery or unrelated documentation.
