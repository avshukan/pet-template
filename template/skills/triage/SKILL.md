# Triage

Read the repository's agent instructions and relevant product, decision and
process documentation. Locate existing work records using the documented
conventions; do not assume a backlog file, tracker, labels or states exist.

Inspect the request and relevant repository evidence. Separate observed facts,
proposals, accepted owner decisions and open questions. Cite the files or records
supporting material conclusions, and label assumptions when evidence is missing.

Check scope, overlap with existing work, impact, dependencies and missing
information. Recommend a proportionate next action: clarification, readiness
assessment, linking to existing work, deferral or no further action. Explain
priority suggestions using the repository's criteria, if any.

Return a concise assessment with evidence, the recommendation and any owner
decisions needed. Use existing record formats when available; otherwise report
in the conversation. Do not invent IDs, backlog structures or workflow machinery.
Do not treat triage as approval to implement, accept product/process changes or
merge. Update shared records only within the owner's authorized scope, keeping
recommendations distinct from accepted decisions.
